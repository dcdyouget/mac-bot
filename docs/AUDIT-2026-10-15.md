答案 inbox 写入失败的独立脚本另有两处配置错误：等待了基类不会设置的 Event，随后又给类属性而非模块常量赋答案字符串。其 timeout / count=0 不能证明产品丢答。真实捕获显示答案仍在 system 的群历史中，但本轮加入的文本去重会删除明确的 user 输入；该启发式已移除，消费去重必须依据输入身份。最终回归以明确 user 输入、同 run 及持久消费状态为准，不以整段 JSON 的字符串出现次数代替业务语义。

S-13 首轮修复还引入了另一处整合回归：仅以 delivery=queued 排除即时输入，误伤明确 @Bot 的消息。最终真实产品闭环的 worker prompt 缺少插话 marker，强断言失败后继续修复；该回归不算初始用户代码缺陷。入口必须按 @、回复、引用各自语义区分，不能从单个送达状态反推用户意图。

### 故障边界与证据强度

| 边界 | 本轮实际验证 | 不能据此推出的结论 |
|---|---|---|
| 请求落盘 / 响应返回 | S-07 真实 RPC：WAL 成功、快照失败后同 ID 重试只产生一个项目；桌面 outbox 与 Android 成功回包后连接换代回归保留逻辑 ID | 不证明任意外部服务都支持幂等，也不证明所有 RPC 都已做逐个故障注入 |
| 调度 / 等待后重新准入 | S-02 四种真实 provider 并发矩阵；等待释放名额，再按 Bot/global/同群约束排队；交叉群实际并行 | 不以单元 helper 或 mock 成功代替生产调度；完整整合验收状态见 S-02 |
| 工具执行 / 结果落盘 | routine 执行中 kill9 后原 job 保持 suspended、实际文件只有一次写入；S-08 continuation 的未知结果场景另行验收 | 不能保证恰好一次外部副作用；无法判定结果的调用须暂停，不能盲目重放 |
| WAL / 内存 / JSON 快照 | S-05 durable API 文件故障注入；S-06 真实取消链快照失败保留准入屏障，同 ID 重试完成清理 | 未模拟磁盘控制器故障、文件系统损坏或断电后的硬件写缓存行为 |
| 发布事件 / 补发边界 | S-01 真实 WebSocket 补发期间新事件竞争；两端缺口、重复、乱序与 bootstrap/replay 回归 | 未在每一种业务 mutation 的每一条文件系统指令之间逐点杀进程 |

### 明确未覆盖及保留限制

- 各模块与产品入口均有静态盘点，核心故障路径有定向运行证据；未逐一实测所有页面的全部加载、空、权限不足、过期与重试组合，也未做全量视觉像素验收。
- 两端已实际连接独立 mock；Android 保存了关键 PNG，桌面仅有现场 CUA 图像、AX 与 RPC 证据，系统屏幕录制权限限制使 PNG 导出未完成。未更改系统隐私权限规避限制。
- 使用独立本机服务模拟任意 Host 的网络与文件归属；公网远程 TLS、真实高延迟网络、真实 Chrome/agent-browser 全流程、系统推送、正式签名公证与安装包分发未验收。
- Android Provider 表单未独立重复跨 Host UI 流程；Trace 的 live 标志代理只验证客户端订阅归属，不证明真实服务端 live 数据。桌面 100 MiB 附件上限有核心回归，未用 GUI 上传边界大小文件。
- 用户记忆 CAS、技能路径、工作台和通知进行了入口与实现审查，未对全部后端 provider 或实际用户记忆数据做迁移/破坏性验证。仅保留用户记忆页面，未增加 Bot 或项目记忆入口。
- 子运行目前被只读工具 allowlist 限制，未发现可达的独立提问/审批 continuation；若未来开放这些工具，共享父 assignment 的完成和名额归属须重新设计，详见服务端补充链路。这是条件性风险，不计为本轮已复现缺陷。
- macOS 的 Unix socket 路径有长度限制：过长的临时 home 导致 daemon 创建 `data/macbotd.sock` 时以 `path must be shorter than SUN_LEN` 退出。产品闭环换用短隔离目录后通过，未通过延长超时掩盖启动失败；本轮未改变 socket 地址机制。
- 早期插话仍有未复现的时序风险：任务已可见，但 run request / durable job 连续超过约一秒不可见时，`enqueue_steer_runtime` 的有限等待可能用尽；canonical steer 已持久化，但未找到向 inbox 补入的通用恢复路径。现有可控 provider gate 位于 job 创建之后，无法验证这个更早窗口；未通过篡改任务文件制造“复现”。该项保留为待验证风险，不能宣称已排除所有插话丢失窗口。

# Mac Bot 设计文档 v2.0（组件、界面与交互）

> 状态：设计稿，尚未编码。本文回答三个问题：系统分成哪些组件、每个组件提供哪些界面和功能、界面长什么样。
> 技术实现（数据模型、调度、上下文、协议）见 [PLAN.md](PLAN.md)。两份文档有冲突时，**界面和交互以本文为准，后端实现以 PLAN.md 为准**。
> 视觉参考 Grok Bot 官方截图（见附录 A）；协作模式参考日常工作中「一件事拉一个群」的做法。

## 0. 一页总览

```text
    ┌──────────────────────────── Bot 主机（你的 Mac mini） ─────────────────────────────┐
    │ macbotd（无界面守护进程，一个端口 7788，一个访问密码）                             │
    │  ├ Gateway        /ws  /api/v1  /admin                                             │
    │  ├ Bot Runtime    两段式输出（发言 / 干活）、并发调度、审批、插话                  │
    │  ├ Orchestrator   ★ 主 Bot 调度、群路由、任务流转、交接、防循环                    │
    │  ├ Memory         用户记忆 / Bot 记忆 / 项目记忆 + 自动上下文管理                  │
    │  ├ Providers      自定义模型（OpenAI 兼容 / Anthropic / Google …）                 │
    │  ├ Scheduler      定时任务 · 用量统计（每次模型调用都记账）                        │
    │  ├ Browser        agent-browser sidecar：每个 Bot 一个浏览器会话 + 画面流          │
    │  ├ Store          SQLite                                                           │
    │  ├ Admin Web      /admin 极简管理页                                                │
    │  └ CLI            macbot status | passwd | logs | restart                          │
    └──────────────────────────────────────────┬─────────────────────────────────────────┘
                                               │ ws(s)://host:7788 + 密码
                  ┌────────────────────────────┼───────────────────────────┐
                  │                            │                           │
      桌面客户端（macOS，GPUI）         Android 客户端                iOS 客户端
              完整功能                    └─ Compose Multiplatform，同一套代码 ─┘
```

| # | 组件 | 运行在哪里 | 形态 | 用户能看到的界面 |
|---|------|-----------|------|------------------|
| 1 | **macbotd 服务端** | Bot 主机（Mac） | 无界面守护进程 | 无（通过客户端使用） |
| 2 | **Web 管理页** | 服务端内置 | 浏览器打开 `/admin` | 首次设置密码、运行状态、端口、日志、重启 |
| 3 | **CLI `macbot`** | Bot 主机终端 / SSH | 命令行 | `status` / `passwd` / `logs` / `restart` |
| 4 | **桌面客户端** | 任意 Mac | GPUI App | **全部功能**（第 4 章） |
| 5 | **移动客户端** | Android / iOS | Compose MP App | 消息、群、审批、工作台、实时画面和接管、统计（第 5 章） |
| 6 | **agent-browser** | Bot 主机 | sidecar 进程 | 无（它推送的画面在客户端的 Agent Computer 里显示） |

## 1. 核心概念

| 名词 | 含义 | 界面上的体现 |
|------|------|-------------|
| **主 Bot** ★ | 你的日常对话对象和**所有群的负责人**，默认名「总管」（可以改名）。你把事交给它，它来拉群、拉 Bot、分派任务、跟进，做完后通知你。每台 Host 有且只有一个，不能删除 | 侧栏最上方的固定入口 |
| **Bot** | 负责某个方向的 AI 同事（产品、编码、测试…）。有名字、头衔、长期规则、干活模型、发言模型和并发上限 | 侧栏「Bot」列表 |
| **群** ★ | **一件事 = 一个群 = 一个项目**。群名就是这件事的名字。成员是主 Bot 加 1–6 个 Bot | 侧栏「群」列表 |
| **任务** | 群里分给某个 Bot 的一项具体工作，例如「写 PRD 和原型」。由 @ 或交接产生 | 群里的任务卡片、工作台的一行 |
| **Bot 状态** | 某个 Bot 在**某个群里**的状态：○ 待命 / ⟳ 工作中 / ✓ 完成 / … 排队 / ! 卡住 / ⚠ 等你 | 群头部的状态条、公告、工作台 |
| **两段式输出** ★ | 每个 Bot 都分两路输出：**群里发言**（简短的「收到」「完成了，产物在…，@下一个」）和**干活**（真正执行任务：调用工具、写文件，过程不进群）。干活的过程在「工作详情」里看 | 群消息 vs 工作详情面板 |
| **公告** ★ | 群的置顶信息，**由系统自动维护**：Home 路径、目标、流程、成员分工和状态、每个 Bot 的产物及位置、项目记忆要点 | 群头部的公告条、右侧公告面板 |
| **Home** | 这件事的工作目录 `~/MacBot/projects/<群名>/`，成员 Bot 的产物都放在这里 | 公告里的路径 + [打开] |
| **产物** | Bot 完成任务时交付的文件或链接（PRD、原型、代码、部署地址、测试报告） | 完成消息里的产物卡片、公告的产物清单 |
| **交接** | 一个 Bot 完成后 @ 下一个 Bot，把任务传下去 | 完成消息里的 @，系统事件 |
| **并行** ★ | 同一个 Bot 可以**同时在多个群里干活**（每个群是独立的会话，只是加载的项目记忆不同），并发数有上限；同一个群里同一个 Bot 的活按顺序做 | 工作台「编码 ⟳ 2/3」 |
| **三种记忆** | **用户记忆**（所有 Bot 共享，记录你的习惯）、**Bot 记忆**（每个 Bot 独立，记录自我定义和做过的事）、**项目记忆**（群内共享，就是公告里的要点） | 「✎ 记住了」提示、记忆页（可选） |
| **工作台** | 所有 Bot 正在干的活、排队的活、等你处理的事 | 侧栏 ▦ 工作台 |
| **统计** | 每个 Bot 的 token 消耗、使用的模型、用在了哪些群，以及费用 | 侧栏 ▥ 统计 |

## 2. 设计语言（从 Grok Bot 截图提炼）

**整体风格**：浅色、留白多、贴近 macOS 原生；内容是主角，装饰尽量少。三栏布局，各栏之间用细分隔线。

| Token | 浅色 | 深色 | 用途 |
|-------|------|------|------|
| `bg.window` | `#FFFFFF` | `#1C1C1E` | 主区背景 |
| `bg.sidebar` | `#F5F5F7` | `#232325` | 侧栏、右侧面板 |
| `bubble.bot` | `#EFEFF1` | `#2C2C2E` | Bot 消息气泡 |
| `bubble.user` | `#111111`，白字 | `#F2F2F2`，黑字 | 用户消息气泡（**反色**，Grok 风格） |
| `text.primary` / `secondary` | `#1D1D1F` / `#86868B` | `#F5F5F7` / `#98989D` | 正文 / 次要信息、时间 |
| `accent` | `#2F7BF6` | `#4C8DFF` | 链接、未读点、「⟳ 工作中」 |
| `success` | `#34C759` | 同左 | 「✓ 完成」、定时任务图标 |
| `attention` | `#FF9F0A` | 同左 | 「⚠ 等你」、审批 |
| `danger` | `#FF3B30` | 同左 | 「! 卡住」、出错、删除 |
| `code` | `#D63A5B` 等宽字 | `#FF6B8A` | 行内代码、路径 |

- **字体**：系统字体（SF Pro / PingFang SC）。正文 14，次要信息 12，标题 15 半粗。路径和代码用 SF Mono。
- **圆角**：气泡 18，卡片 14，输入框 22（胶囊形），头像为圆形。
- **间距**：4 / 8 / 12 / 16 / 24。同一个人的连续消息合并头像。
- **图标**：Lucide（gpui-kit 自带）。
- **头像「豆豆」**：彩色圆形豆子加两只眼睛，10 种预设颜色，也可以用 emoji 或图片。**主 Bot 的头像带一个小皇冠**。群头像是成员头像叠放，最多显示 4 个。
- **状态色点**：头像右下角显示 Bot 的综合状态：⟳ 蓝色转圈、⚠ 橙色、! 红色、✓ 绿色闪一下后消失。
- **动效**：工作中的头像外圈转动；新消息淡入 120ms；面板切换滑动 200ms。
- **深色模式**：跟随系统，也可以手动切换。

## 3. 一个完整场景：「给 App 加邮箱登录」

| # | 发生了什么 | 你在哪里看到 |
|---|-----------|-------------|
| 1 | 你在**主 Bot 私聊**里说：「给 App 加个邮箱登录，周六前上线」 | 私聊 |
| 2 | 主 Bot 判断这是一件需要多人配合的事，**建群「登录功能」**，拉入 产品、编码、测试，自己担任负责人；创建 Home 目录 `~/MacBot/projects/login/`；在私聊里发「新群」卡片 | 私聊卡片；侧栏「群」里多出一项 |
| 3 | 主 Bot 在群里发**开场**：事项、目标、截止时间、流程（产品 → 编码 → 测试），并 @产品 交代第一步 | 群；公告自动生成 |
| 4 | **产品**用发言模型回复「收到，开始写 PRD 和原型。」，状态变为 **⟳ 工作中**；群里出现一张任务卡片 | 群消息、状态条、工作台 |
| 5 | 产品在后台**干活**：读需求、写 `product/prd.md`、生成原型。这个过程**不进群**，在任务卡片的「详情」里可以看到 | 工作详情面板 |
| 6 | 产品完成，状态变为 **✓ 完成**，在群里说：「✓ 已完成 PRD 和原型：▤ PRD product/prd.md ▤ 原型 …  @编码 请按 PRD 实现」。产物自动登记到公告 | 群、公告的产物清单 |
| 7 | **编码**收到 @，回复「收到」，状态变为 ⟳ 工作中，开始实现 | 群、工作台 |
| 8 | 你在群里插话「**@编码 先只做邮箱登录，不要手机号**」。编码**正在运行中**，但立即回复「收到，改为只做邮箱登录」，这条指令也插入它正在进行的工作；同时记入项目记忆 | 群、公告的项目记忆、工作详情的「任务指令」 |
| 9 | 与此同时，编码在另一个群「官网改版」里也有活：**两个群并行**，工作台显示「编码 ⟳ 2/3」 | 工作台 |
| 10 | 编码完成：「✓ 已实现并部署到 localhost:3000，代码在 code/。@测试 请测试」 | 群 |
| 11 | 测试完成：「✓ 测试 20/20 通过，报告在 test/report.md」并 @总管 | 群 |
| 12 | 主 Bot 验收，在群里发**完成总结**，把群标记为已完成；然后**在私聊里通知你**，同时发推送 | 群、私聊、手机通知 |
| 13 | 统计页里可以看到每个 Bot 在「登录功能」里消耗了多少 token、用了什么模型 | 统计 |

### 4.2 侧栏

| 元素 | 交互 |
|------|------|
| **Host 切换器**（左上） | 显示当前 Host 和在线点（绿色在线，灰色离线，黄色重连中）。点开后列出所有 Host、「添加 Host…」 |
| **＋ 新建**（`⌘N`） | 新建群或新建 Bot（4.5 ①） |
| **搜索**（`⌘K`） | 搜消息、群、Bot、产物、定时任务 |
| **主 Bot** | 固定在最上方，单独一行，不能隐藏 |
| **群** | 进行中的群，按最近活动排序。每一行显示：成员叠放头像、群名、正在工作的 Bot 数（⟳ 2）或 ⚠、最后一条消息预览。下面折叠着「已完成 N」 |
| **Bot** | 主 Bot 以外的所有 Bot。每一行显示综合状态：○ 空闲 / ⟳ N 个活 / ⚠ 等你。点击打开与它的私聊 |
| **▦ 工作台** | 显示「N 进行中」，有 ⚠ 时变成橙色 |
| **▥ 统计**、ϟ 技能、⚙ 设置 | 底部 |
| 右键菜单 | 群：置顶、重命名、标记完成、归档、通知开关。Bot：置顶、隐藏、通知开关、删除 |

**注意力状态的优先级**：⚠ 等你 > ! 卡住 > ⟳ 工作中 > ● 未读 > 时间。

### 4.3 消息与卡片类型

| 类型 | 样式 | 说明 |
|------|------|------|
| 用户消息 | 右对齐，黑色胶囊气泡 | 支持图片、文件、链接 |
| Bot 发言 | 左对齐，浅灰气泡，Markdown 渲染 | 群里，同一个 Bot 的一串连续消息上方显示头像、名字和头衔 |
| **收到回复** | 普通 Bot 发言，一般只有一句 | Bot 接到任务时**立即**回复，由发言模型生成；同时状态变为 ⟳ |
| **任务卡片** ★ | 「⟳ 任务 · 实现登录 · 已 25 分 · 88k tok  详情」 | 跟在收到回复后面，实时更新用时和 token；完成后变成「✓ … 用时 18 分」。点「详情」打开工作详情 |
| **完成报告** ★ | 「✓ 已完成 …」+ 产物卡片列表 + 对下一个 Bot 的 @ | 由 `complete_task` 生成的结构化消息。产物同时登记到公告 |
| 产物卡片 | ▤ 图标、名称、相对 Home 的路径，[打开] [在 Finder 中显示] | 本机路径直接打开；远程客户端可以预览或下载 |
| **卡住报告** | 「! 卡住：缺少 xx 的 API Key。需要：@你 / @总管」 | 状态变为 ! 卡住或 ⚠ 等你 |
| 进展更新 | 灰色小字「编码：测试已全部通过，正在部署」 | 长任务中的关键节点，频率有限（默认每个任务最多 3 条） |
| 新群卡片 | 「新群 · 名称」+ 目标、成员、负责人 + [进入群] | 主 Bot 在私聊里建群后发出 |
| 完成通知 | 「✓「登录功能」已完成」+ 各 Bot 的产物摘要 + 用时和消耗 + [查看群] [查看产物] | 主 Bot 在私聊里发出，同时推送到手机 |
| 系统事件 | 居中灰字 | 「编码 加入了群」「负责人：总管」「群已标记完成」 |
| 记忆提示 | 灰字「✎ 记入项目记忆：只做邮箱登录」 | 只是提示，不需要操作；悬停时显示「撤销」 |
| 提问卡片 | 问题 + A/B/C 选项 | 选择后折叠成一行 |
| 审批卡片 | 「需要审批 · 工具名」+ 具体内容 + [允许一次] [总是允许] [拒绝] | 只出现在**私聊**里；群里只显示「⚑ 编码 在私聊里等待你审批 前往 →」 |
| 接管请求 | 橙色条「⚑ 需要你接管：……」+ [接管并处理] | 遇到验证码、两步验证、登录时 |
| Bot 间私信卡片 | 「✉ A 私信了 B（N 条） 展开」 | 展开后只读 |
| 正在回复 | 头像 + 「正在回复 …」 | 发言模型正在生成回复时显示 |

**悬停在消息上**会出现：☺ 表情回应、↩ 回复（开线程）、⋯ 更多（复制、引用、删除）。

### 4.4 输入框

- 胶囊形：左边「＋」（附件、图片、截图），中间输入区（`Shift+Enter` 换行），右边发送按钮。
- **`@` 弹出成员选择**：群里列出成员和 `@everyone`，并显示每个成员的状态。**对正在工作的 Bot 发 @，就是插话**：它会立即回复，并把这条指令插进当前的工作。
- `/` 弹出技能列表。
- 群里不 @ 任何人时，消息默认交给**主 Bot** 处理，由它回答或转派。
- 草稿按会话分别保存。

### 4.5 群专章 ★

模仿日常工作的方式：**有一件事 → 拉相关的人进群 → 群名就是这件事 → 大家在群里按流程做完。** 主 Bot 是每个群的负责人。

**① 两种建群方式**

*A. 交给主 Bot（主要方式）*：在主 Bot 私聊里说「帮我做 xxx」。
- 满足以下任一条件时，主 Bot 会建群：需要别的 Bot 参与、要跨多次对话、有需要沉淀的产出物、你明确说要建群。
- 建群时，它挑选成员、写好目标和流程，在私聊里发一张新群卡片，然后在群里开场。整个过程不需要你确认。
- 小事（查天气、翻译）直接在私聊里回答。
- 找不到合适的 Bot 时，它会问你：「要不要新建一个『测试』Bot？」**新建 Bot 必须经过你同意**。

*B. 手动*：`⌘N` → 输入一件事 →「新建群」→ 勾选成员 → 填目标。主 Bot 会自动加入并在群里开场。

```text
┌────────────────────────────────────────────────────────────────┐
│ 新建                                                    ✕      │
│ ⌕ 输入一件事（建群），或一个名字（新建 Bot）                   │
│ ────────────────────────────────────────────────────────────   │
│ ＋ 新建群「官网改版」     总管会自动加入并担任负责人           │
│ ＋ 新建 Bot「官网改版」                                        │
│ ────────────────────────────────────────────────────────────   │
│ 选择成员（1–6 个，已选 2，另加总管）                           │
│ [✓] (P) 产品           PRD、原型                               │
│ [✓] (C) 编码           写代码、部署                            │
│ [ ] (T) 测试           测试、回归                              │
│ [ ] (R) 调研           资料调研                                │
│                                                                │
│ 目标    [ 首页改成新品牌风格，下周一上线               ]       │
│                                                                │
│                                           [取消]  [建群]       │
│ 建群后，总管会在群里发开场：说明事项、流程，@ 第一个 Bot       │
└────────────────────────────────────────────────────────────────┘
```

**② 群头部与状态条**
- 第一行：成员叠放头像、群名、状态（进行中 / 已完成）。
- 第二行是**状态条**，例如「总管 ★ · 产品 ✓完成 · 编码 ⟳工作中 · 测试 ○待命」。点某个成员，就打开他在这个群的工作详情。
- 第三行是**公告条**：「公告 Home ~/MacBot/projects/login/ · 产物 3 ▾」，点开后右侧显示完整公告。

**③ 公告（系统自动维护，用户不用写）**

│ ──────────────────────────────────────────────────────────────────   │
│ 成员      分工                     状态           当前任务           │
│ (Z) 总管  负责人、协调、验收        ★              —                 │

│ (C) 编码  实现、部署                ⟳ 工作中 25 分  实现登录         │

│ 产物                                  作者    更新                   │

- 只有「项目记忆」部分可以手动编辑，其余由系统根据事件实时更新。
- 成员 Bot 每次干活时都会读到公告，这就是项目的共享上下文。

**④ 谁来回应**

| 你发的消息 | 谁回应 | 说明 |
|-----------|--------|------|
| `@编码 …` | 编码 | 编码空闲时，这条消息成为新任务；编码正在干这个群的活时，就是**插话**（见 ⑥） |
| `@产品 @编码 …` | 被 @ 的两个 Bot | 各自回应 |
| `@everyone …` | 所有成员 | |
| ↩ 回复某条消息 | 那条消息的发送者 | 在右侧面板以线程形式进行 |
| 不 @ 任何人 | **主 Bot** | 由它回答，或者转派给合适的成员（转派时会 @ 对方） |

**⑤ 任务流转：收到 → 工作中 → 完成 → @下一个**

```text
  @编码（来自你、主 Bot 或上一个 Bot 的完成报告）
      │
      ▼
  [发言] 「收到，开始实现。」        状态 ○ → ⟳ 工作中，出现任务卡片
      │
      ▼
  [干活] 读 PRD、写代码、跑测试、部署   过程只在工作详情里显示
      │            ▲
      │            └── 插话：「@编码 只做邮箱」→ [发言]「收到，正在调整」+ 指令插进当前工作
      ▼
  [发言] 完成报告：✓ 已完成… ▤ 产物… @测试 请测试     状态 → ✓ 完成；产物登记到公告；测试收到任务
      │
      ├─ 卡住：「! 卡住：… 需要 @你」             状态 → ! 卡住 / ⚠ 等你；主 Bot 跟进
      └─ 流程最后一个 Bot 完成 → @总管 → 主 Bot 验收、写总结、标记完成、在私聊里通知你
```

**⑥ 插话（Bot 运行中也可以 @ 它指导和修改）**
- 被 @ 的 Bot 正在这个群里干活时，系统做三件事：
  1. 用发言模型**立即**回复，例如「收到，改为只做邮箱登录」。
  2. 把这条指令插进它正在进行的工作，在下一步生效，不会等它做完。
  3. 如果是一条决定，记入项目记忆。
- 说「@编码 停一下」或在工作详情里点 [停止]，会中止当前任务，状态变为 ○ 待命。
- 被 @ 的 Bot 正在**别的群**里干活不受影响：每个群是独立的会话，可以并行。

**⑦ 交接、私信、防循环**
- 完成报告里的 @ 就是交接：下一个 Bot 收到任务，同时拿到上一个 Bot 的产物清单和说明。
- Bot 之间的私信不在群里刷屏，以「✉ A 私信了 B」卡片的形式出现。
- 同一条用户消息引发的 Bot 间往返超过 8 次，出现横幅「⏸ 已暂停」，并提供 [再允许 8 次] [结束这一轮]。

**⑧ 线程**（点消息上的「↩ 回复」后，在右侧面板打开）

```text
┌──────────────────────────────┐
│ ‹   线程 · Analyst   »       │
│                              │
│ (A) 数据在 shared/metr…      │
│ ──────────────────────────   │
│ (E) 周活口径是 7 日？        │
│ (A) 是，7 日去重。           │
│                              │
│ ( 回复 Analyst… )            │
└──────────────────────────────┘
```

**⑨ 生命周期**

| 状态 | 怎么进入 | 侧栏 | 发生什么 |
|------|---------|------|---------|
| 进行中 | 创建 | 「群」列表 | 按流程协作 |
| 已完成 | 主 Bot 验收后标记，或者你点 [标记完成] | 折叠到「已完成 N」 | 主 Bot 在群里发总结，写入项目记忆；每个成员的工作记录追加一条；主 Bot **在私聊里通知你，同时推送** |
| 重新打开 | 在已完成的群里发消息 | 回到「群」列表 | 继续协作 |
| 已归档 | 手动 | 不显示，可以搜到 | Home 目录、记忆和记录都保留 |

### 4.13 状态与异常

| 场景 | 表现 |
|------|------|
| Host 断线 | 侧栏 Host 点变黄，顶部出现细条「正在重连…」；本地缓存可以浏览，输入框禁用 |
| 重连成功 | 按 `last_seq` 补齐断线期间的事件 |
| 模型报错 | 任务卡片变红：错误摘要 + [重试] [换模型]；如果错误持续，主 Bot 会在群里跟进 |
| 服务端重启 | 进行中的任务自动恢复，任务卡片上显示「已恢复」 |
| 并发已满 | 新任务显示「… 排队」，并注明原因 |
| 空状态 | 没有群时，「群」列表显示「对总管说『帮我做…』，它会拉群去做」 |

## 8. 服务端组件与界面的对应关系

| 组件 | 职责 | 驱动哪些界面 |
|------|------|-------------|
| Gateway | 一个端口、密码鉴权、`/ws` 事件流（带 seq，断线可补发）、`/api/v1`、`/admin` | 所有客户端 |
| **Orchestrator** ★ | 主 Bot 建群；群消息路由（@、回复、没 @ 时交给主 Bot）；任务的创建、流转、交接；插话投递；防循环 | 群、状态条、任务卡片、完成报告 |
| **Bot Runtime** ★ | **两段式输出**：发言（快、短、不带工具）和干活（长、带工具、可以恢复）；审批；停止 | 收到回复、工作详情、审批卡片 |
| **Scheduler** ★ | 并发调度：全局上限、每个 Bot 的上限、同一个群内同一个 Bot 串行；排队；定时任务 | 工作台、排队原因 |
| Projects | 群（= 项目）、Home 目录、产物登记、公告生成、生命周期 | 公告、产物卡片、侧栏 |
| Memory | 三种记忆、自动分段和压缩、检索、后台整理 | 「✎ 记住了」提示、记忆页 |
| **Usage** ★ | 每次模型调用都记账：Bot、群、任务、阶段、模型、token、费用 | 统计、任务卡片上的 token 数 |
| Providers | 服务商和模型目录、流式输出、单价 | 模型设置 |
| Browser | 每个（Bot，群）一个 agent-browser 会话；画面流代理 | Agent Computer |
| Store | SQLite | 搜索、断线补发 |

**客户端订阅的主要事件**：`project.created` / `project.updated` · `task.created` / `task.updated`（状态、用时、token）· `artifact.registered` · `announcement.updated` · `message.created` / `message.delta` · `work.step`（工作过程）· `bot.status`（综合状态、并发数）· `approval.requested` / `approval.resolved` · `usage.tick` · `screen.frame` / `screen.url` · `host.status`

## 附录 A：Grok Bot 界面要点（参考来源）

- 三栏布局：侧栏 / 会话 / 右侧上下文面板。侧栏有分组、置顶头像磁贴、「Hidden Bots N」。
- 用户消息是黑色气泡，Bot 消息是浅灰气泡；提问卡片用 A/B/C 选项；任务卡片带「Running」状态和操作按钮。
- 右侧面板默认显示「X's screen」和 Routines；⚙ 进入 Settings；定时任务页有 Active 开关、Delete、Test run、Instruction、When to run、Run history。
- 电脑视图覆盖整个窗口，右上角是「Teach a task」和收起按钮。
- 群聊：2–6 个 Bot；不 @ 时由 Bot 自己决定谁回应；用回复形成线程；审批、密码请求和草稿不在群里出现；群有 Group name 和 Description。
- 审批：Allow once / Always allow / Deny。

Mac Bot 在 Grok 的基础上新增了：**主 Bot 当负责人**、**两段式输出（群里发言 / 干活）**、**系统维护的公告和产物清单**、**按群并行**、**工作台**和**统计**。

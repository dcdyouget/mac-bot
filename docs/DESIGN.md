# Mac Bot 设计文档 v3.1（组件、界面与交互）

> 状态：设计稿，尚未编码。本文回答三个问题：系统分成哪些组件、每个组件提供哪些界面和功能、界面长什么样。
> **本文是产品行为和界面的唯一权威来源。** 服务端实现见 [PLAN.md](PLAN.md)，协议字段见 [PROTOCOL.md](PROTOCOL.md)；文档地图见 PLAN 第 0 章。
> 视觉参考 Grok Bot 官方截图（见附录 A）；协作模式参考日常工作中「一件事拉一个群」的做法。

## 0. 一页总览

```text
    ┌──────────────────────────── Bot 主机（你的 Mac mini） ─────────────────────────────┐
    │ macbotd（无界面守护进程，一个端口 7788，一个访问密码）                             │
    │  ├ Gateway        /ws  /api/v1  /admin                                             │
    │  ├ Bot Runtime    durable 执行、send_msg 发群消息、并发调度、审批、插话            │
    │  ├ Orchestrator   ★ 主 Bot 调度、群路由、任务流转、交接、防循环                    │
    │  ├ Memory         用户记忆 / Bot 记忆 / 项目记忆 + 自动上下文管理                  │
    │  ├ Providers      自定义模型（OpenAI 兼容 / Anthropic / Google …）                 │
    │  ├ Scheduler      定时任务 · 用量记账（仪表盘的数据来源）                          │
    │  ├ Browser        agent-browser sidecar：每个 Bot 一个浏览器会话 + 画面流          │
    │  ├ Store          JSON 文件（JSONL 日志 + 快照，无数据库）                         │
    │  ├ Admin Web      /admin 极简管理页                                                │
    │  └ CLI            macbot status | passwd | logs | restart                          │
    └──────────────────────────────────────────┬─────────────────────────────────────────┘
                                               │ ws(s)://host:7788 + 密码
                  ┌────────────────────────────┼───────────────────────────┐
                  │                            │                           │
      桌面客户端（macOS，GPUI）         Android 客户端                iOS 客户端
              完整功能                    └─ Compose Multiplatform，同一套代码 ─┘
```

| # | 组件 | 运行在哪里 | 形态 | 用户能看到的界面 |
|---|------|-----------|------|------------------|
| 1 | **macbotd 服务端** | Bot 主机（Mac） | 无界面守护进程 | 无（通过客户端使用） |
| 2 | **Web 管理页** | 服务端内置 | 浏览器打开 `/admin` | 首次设置密码、运行状态、端口、日志、重启 |
| 3 | **CLI `macbot`** | Bot 主机终端 / SSH | 命令行 | `status` / `passwd` / `logs` / `restart` |
| 4 | **桌面客户端** | 任意 Mac | GPUI App | **全部功能**（第 4 章） |
| 5 | **移动客户端** | Android / iOS | Compose MP App | 消息、群、审批、验收、工作台、实时画面和接管、仪表盘（第 5 章） |
| 6 | **agent-browser** | Bot 主机 | sidecar 进程 | 无（它推送的画面在客户端的 Agent Computer 里显示） |

## 1. 核心概念

| 名词 | 含义 | 界面上的体现 |
|------|------|-------------|
| **主 Bot** ★ | 你的日常对话对象和**所有群的负责人**，默认名「总管」（可以改名）。**它只协调，不干活**：拉群、拉 Bot、分派任务、跟进进度，做完后提醒你验收。需要动手的小事，它转给合适的 Bot 去做。每台 Host 有且只有一个，不能删除 | 侧栏最上方的固定入口 |
| **Bot** | 负责某个方向的 AI 同事（产品、编码、测试…）。有名字、头衔、长期规则、模型和并发上限 | 侧栏「Bot」列表 |
| **群** ★ | **一件事 = 一个群 = 一个项目**。群名就是这件事的名字。成员是主 Bot 加 1–6 个 Bot | 侧栏「群」列表 |
| **任务** | 群里分给某个 Bot 的一项具体工作，例如「写 PRD 和原型」。由 @ 或交接产生 | 群里的任务卡片、工作台的一行 |
| **Bot 状态** | 某个 Bot 在**某个群里**的状态：○ 待命 / ⟳ 工作中 / ✓ 完成 / … 排队 / ! 卡住 / ⚠ 等你 | 群头部的状态条、公告、工作台 |
| **待验收** ◎ | 群里所有活都做完后，主 Bot 汇总产物并提醒你验收。你点「确认完成」，群才算完成 | 私聊里的待验收卡片、工作台顶部 |
| **群消息 = `send_msg`** ★ | Bot 收到任务后按 durable 流程在后台干活，**过程不进群**。只有在开工、阶段进展、需要决策、完成、卡住时，它才调用 `send_msg` 工具往群里发**一条完整的消息**（不流式）。私聊则是普通对话，回复可以流式显示 | 群消息 vs 工作详情 |
| **公告** ★ | 群的置顶信息，**由系统自动维护**：Home 路径、目标、流程、成员分工和状态、每个 Bot 的产物及位置、项目要点（只读） | 群头部的公告条、右侧公告面板 |
| **Home** | 这件事的工作目录 `~/MacBot/projects/<群名>/`，成员 Bot 的产物都放在这里 | 公告里的路径 + [打开] |
| **产物** | Bot 完成任务时交付的文件或链接（PRD、原型、代码、部署地址、测试报告） | 完成消息里的产物卡片、公告的产物清单 |
| **交接** | 一个 Bot 完成后 @ 下一个 Bot，把任务传下去 | 完成消息里的 @，系统事件 |
| **并行** ★ | 同一个 Bot 可以**同时在多个群里干活**（每个群是独立的会话，只是加载的项目记忆不同），并发数有上限；同一个群里同一个 Bot 的活按顺序做 | 工作台「编码 ⟳ 2/3」 |
| **记忆** | 用户记忆、Bot 记忆、项目记忆三种，**完全由服务端管理**：客户端不展示、也不编辑。你唯一能看到的是公告里的「项目要点」（项目记忆的只读摘录） | 公告的「项目要点」 |
| **运行轨迹** ★ | Bot **干活这一路**的完整过程：每次模型请求（上下文大小、token、耗时、费用）、流式输出和思考、每次工具调用（参数、实时输出、结果）、子代理、插话。进行中可以实时看，结束后可以回放 | 工作详情、全屏轨迹视图、Bot 的历史任务 |
| **子代理** | Bot 干活时临时叫来的「帮手」，用来查资料、读大量文件、做并行的小任务，**只把结论交回**，从而保持 Bot 自己的上下文干净。**子代理不是 Bot**：没有名字、没有记忆，不进群，用完就结束 | 工作详情里的「⇢ 子代理 ×3」 |
| **工具** | Bot 干活时能用的能力：文件（读、写、改、找）、bash、浏览器（agent-browser）、子代理、网页、协作和记忆。每个 Bot 可以单独开关 | Bot 设置里的工具开关、工作详情 |
| **技能（Skill）** | 可以复用的做事说明（`SKILL.md` + 附带的脚本和资料），**所有 Bot 共用**。Bot 根据描述在需要时自己加载，也可以用 `/技能名` 强制使用 | 侧栏 ϟ 技能 |
| **工作台** | 所有 Bot 正在干的活、排队的活、等你处理的事（审批、验收） | 侧栏 ▦ 工作台 |
| **仪表盘** | 类似 OpenAI 用量页：热力图、每日 token 折线（按模型 / Bot / 项目切换）、明细表 | 侧栏 ▥ 仪表盘 |

## 2. 设计语言（从 Grok Bot 截图提炼）

**整体风格**：浅色、留白多、贴近 macOS 原生；内容是主角，装饰尽量少。三栏布局，各栏之间用细分隔线。

| Token | 浅色 | 深色 | 用途 |
|-------|------|------|------|
| `bg.window` | `#FFFFFF` | `#1C1C1E` | 主区背景 |
| `bg.sidebar` | `#F5F5F7` | `#232325` | 侧栏、右侧面板 |
| `bubble.bot` | `#EFEFF1` | `#2C2C2E` | Bot 消息气泡 |
| `bubble.user` | `#111111`，白字 | `#F2F2F2`，黑字 | 用户消息气泡（**反色**，Grok 风格） |
| `text.primary` / `secondary` | `#1D1D1F` / `#86868B` | `#F5F5F7` / `#98989D` | 正文 / 次要信息、时间 |
| `accent` | `#2F7BF6` | `#4C8DFF` | 链接、未读点、「⟳ 工作中」 |
| `success` | `#34C759` | 同左 | 「✓ 完成」、定时任务图标 |
| `attention` | `#FF9F0A` | 同左 | 「⚠ 等你」、审批 |
| `danger` | `#FF3B30` | 同左 | 「! 卡住」、出错、删除 |
| `code` | `#D63A5B` 等宽字 | `#FF6B8A` | 行内代码、路径 |

- **字体**：系统字体（SF Pro / PingFang SC）。正文 14，次要信息 12，标题 15 半粗。路径和代码用 SF Mono。
- **圆角**：气泡 18，卡片 14，输入框 22（胶囊形），头像为圆形。
- **间距**：4 / 8 / 12 / 16 / 24。同一个人的连续消息合并头像。
- **图标**：Lucide（gpui-kit 自带）。
- **头像「豆豆」**：彩色圆形豆子加两只眼睛，10 种预设颜色，也可以用 emoji 或图片。**主 Bot 的头像带一个小皇冠**。群头像是成员头像叠放，最多显示 4 个。
- **状态色点**：头像右下角显示 Bot 的综合状态：⟳ 蓝色转圈、⚠ 橙色、! 红色、✓ 绿色闪一下后消失。
- **动效**：工作中的头像外圈转动；新消息淡入 120ms；面板切换滑动 200ms。
- **深色模式**：跟随系统，也可以手动切换。

## 3. 一个完整场景：「给 App 加邮箱登录」

| # | 发生了什么 | 你在哪里看到 |
|---|-----------|-------------|
| 1 | 你在**主 Bot 私聊**里说：「给 App 加个邮箱登录，周六前上线」 | 私聊 |
| 2 | 主 Bot 判断这是一件需要多人配合的事，**建群「登录功能」**，拉入 产品、编码、测试，自己担任负责人（只协调不干活）；创建 Home 目录 `~/MacBot/projects/login/`；在私聊里发「新群」卡片 | 私聊卡片；侧栏「群」里多出一项 |
| 3 | 主 Bot 在群里发**开场**：事项、目标、截止时间、流程（产品 → 编码 → 测试），并 @产品 交代第一步 | 群；公告自动生成 |
| 4 | 产品接到任务，状态立即变为 **⟳ 工作中**，群里出现一张任务卡片（这是系统根据状态生成的，不是 Bot 说的话）。产品的第一步是调用 `send_msg(ack)`：「收到，开始写 PRD 和原型。」 | 群消息、状态条、工作台 |
| 5 | 产品在后台**干活**：加载技能「prd-template」，叫 3 个**子代理**并行调研同类产品的登录流程（只把结论交回），然后写 `product/prd.md`、生成原型。这个过程**不进群**，在任务卡片的「详情」里可以看到 | 工作详情面板 |
| 6 | 产品调用 `send_msg(done, 产物, @编码)`，群里出现一条完整的完成消息：「✓ 已完成 PRD 和原型：▤ PRD product/prd.md ▤ 原型 …  @编码 请按 PRD 实现」。状态变为 **✓ 完成**，产物自动登记到公告，编码收到任务 | 群、公告的产物清单 |
| 7 | **编码**收到 @，回复「收到」，状态变为 ⟳ 工作中，开始实现 | 群、工作台 |
| 8 | 你在群里插话「**@编码 先只做邮箱登录，不要手机号**」。编码**正在运行中**，这条消息作为插话进入它的 durable 流程，在下一步生效；你的消息下面显示「已送达」→「编码 已读取」。编码读到后用 `send_msg(progress)` 回复「收到，改为只做邮箱登录」。服务端把这条决定记入项目记忆，公告的「项目要点」里会出现它 | 群、送达状态、工作详情的「任务指令」、公告 |
| 9 | 与此同时，编码在另一个群「官网改版」里也有活：**两个群并行**，工作台显示「编码 ⟳ 2/3」 | 工作台 |
| 10 | 编码完成：「✓ 已实现并部署到 localhost:3000，代码在 code/。@测试 请测试」 | 群 |
| 11 | 测试完成：「✓ 测试 20/20 通过，报告在 test/report.md」并 @总管 | 群 |
| 12 | 主 Bot **汇总产物**，把群状态改为 **◎ 待验收**，然后在私聊里**提醒你验收**（附产物清单），同时推送到手机。主 Bot 自己不检查代码 | 私聊的待验收卡片、手机通知、工作台 |
| 13 | 你看完后点 **[确认完成]**，群标记为已完成，主 Bot 在群里发总结；如果点 **[提修改意见]**，主 Bot 把你的意见派给对应的 Bot，流程继续 | 私聊、群 |
| 14 | 仪表盘里可以看到每个 Bot 在「登录功能」里消耗了多少 token、用了什么模型，以及每天的趋势 | 仪表盘 |

### 4.3 消息与卡片类型

| 类型 | 样式 | 说明 |
|------|------|------|
| 用户消息 | 右对齐，黑色胶囊气泡 | 支持图片、文件、链接 |
| Bot 消息 | 左对齐，浅灰气泡，Markdown 渲染 | **群里每条 Bot 消息都来自它调用的 `send_msg`，是完整的一条，不流式**。同一个 Bot 的一串连续消息上方显示头像、名字和头衔。私聊里 Bot 的回复是普通对话，可以流式显示 |
| 收到（ack） | 普通 Bot 消息，一般只有一句 | Bot 开工后的第一步 `send_msg(ack)` |
| **任务卡片** ★ | 「⟳ 任务 · 实现登录 · 已 25 分  详情」 | **系统根据任务状态生成**，不是 Bot 说的话；只在状态变化时更新（排队 → 工作中 → 等待 → 完成），不显示 token。点「详情」打开工作详情 |
| **完成报告** ★ | 「✓ 已完成 …」+ 产物卡片列表 + 对下一个 Bot（或主 Bot）的 @ | `send_msg(done)` 生成的结构化消息；产物同时登记到公告，交接对象收到新任务 |
| **送达状态** | 用户气泡下方的小字：「已送达 · 等下一步」→「编码 已读取 ✓」 | 你 @ 一个正在干活的 Bot 时，消息作为插话进入它的流程，Bot 不会立刻回复；读到之后它会自己用 send_msg 回应 |
| 产物卡片 | ▤ 图标、名称、相对 Home 的路径，[打开] [在 Finder 中显示] | 本机路径直接打开；远程客户端可以预览或下载 |
| **卡住报告** | 「! 卡住：缺少 xx 的 API Key。需要：@你 / @总管」 | 状态变为 ! 卡住或 ⚠ 等你 |
| 阶段进展 | 灰色小字「编码：测试已全部通过，正在部署」 | `send_msg(progress)`，每个任务最多 3 条 |
| 新群卡片 | 「新群 · 名称」+ 目标、成员、负责人 + [进入群] | 主 Bot 在私聊里建群后发出 |
| 转交提示 | 「↪ 交给 调研 处理（不建群）」，后面跟着那个 Bot 的回复 | 主 Bot 不干活，需要动手的小事会转给合适的 Bot，结果直接回到私聊 |
| **待验收卡片** ★ | 「待验收 · 群名」+ 产物清单（名称、位置、作者）+ [确认完成] [提修改意见] [进入群] | 主 Bot 在私聊里发出，同时推送到手机；点「提修改意见」后输入意见，主 Bot 会派给对应的 Bot |
| 系统事件 | 居中灰字 | 「编码 加入了群」「群进入待验收」「你已确认完成」 |
| 提问卡片 | 问题 + A/B/C 选项 | 选择后折叠成一行 |
| 审批卡片 | 「需要审批 · 工具名」+ 具体内容 + [允许一次] [总是允许] [拒绝] | 只出现在**私聊**里；群里只显示「⚑ 编码 在私聊里等待你审批 前往 →」 |
| 接管请求 | 橙色条「⚑ 需要你接管：……」+ [接管并处理] | 遇到验证码、两步验证、登录时 |
| Bot 间私信卡片 | 「✉ A 私信了 B（N 条） 展开」 | 展开后只读 |
| 正在输入 | 头像 + 「正在输入 …」 | **只在私聊里**显示；群里用状态条和任务卡片表示「工作中」 |

**悬停在消息上**会出现：☺ 表情回应、↩ 回复（开线程）、⋯ 更多（复制、引用、删除）。

### 4.4 输入框

- 胶囊形：左边「＋」（附件、图片、截图），中间输入区（`Shift+Enter` 换行），右边发送按钮。
- **`@` 弹出成员选择**：群里列出成员和 `@everyone`，并显示每个成员的状态。**对正在工作的 Bot 发 @，就是插话**：消息进入它的流程，在下一步生效，气泡下方显示送达状态；它读到后会自己用 `send_msg` 回应。
- `/` 弹出技能列表。
- 群里不 @ 任何人时，消息默认交给**主 Bot** 处理，由它回答或转派。
- 草稿按会话分别保存。

### 4.5 群专章 ★

模仿日常工作的方式：**有一件事 → 拉相关的人进群 → 群名就是这件事 → 大家在群里按流程做完。** 主 Bot 是每个群的负责人。

**① 两种建群方式**

*A. 交给主 Bot（主要方式）*：在主 Bot 私聊里说「帮我做 xxx」。主 Bot 只协调，不干活。
- 满足以下任一条件时，主 Bot 会建群：需要别的 Bot 参与、要跨多次对话、有需要沉淀的产出物、你明确说要建群。
- 建群时，它挑选成员、写好目标和流程，在私聊里发一张新群卡片，然后在群里开场。整个过程不需要你确认。
- 闲聊和纯知识问答，主 Bot 直接回答；需要动手的小事（查资料、改个文件），它**转给一个合适的 Bot** 去做，不建群，结果回到私聊。
- 找不到合适的 Bot 时，它会问你：「要不要新建一个『测试』Bot？」**新建 Bot 必须经过你同意**。

*B. 手动*：`⌘N` → 输入一件事 →「新建群」→ 勾选成员 → 填目标。主 Bot 会自动加入并在群里开场。

**④ 谁来回应**

| 你发的消息 | 谁回应 | 说明 |
|-----------|--------|------|
| `@编码 …` | 编码 | 编码空闲时，这条消息成为新任务；编码正在干这个群的活时，就是**插话**（见 ⑥） |

| 不 @ 任何人 | **主 Bot** | 由它回答，或者转派给合适的成员（转派时会 @ 对方） |

**⑤ 任务流转：Bot 按 durable 流程干活，只在关键节点用 `send_msg` 发言**

```text
  @编码（来自你、主 Bot，或者上一个 Bot 在 send_msg 里 @ 了它）
      │
      ▼
  系统：状态 ○ → ⟳ 工作中（排不上就 … 排队），群里出现任务卡片
      │
      ▼
  durable 流程（后台）：模型请求 → 工具调用 → 子代理 → …      过程不进群，只在工作详情里看
      │   ├─ send_msg(ack)       「收到，开始实现。」                         第一步
      │   ├─ send_msg(progress)  「测试已全部通过，正在部署」                阶段节点，最多 3 条
      │   ├─ send_msg(decision)  「登录失败要不要锁账号？A 锁 B 不锁 @你」   挂起等待，你回复后继续
      │   └─ 插话：「@编码 只做邮箱」→ 下一步注入 → 送达状态「已读取」→ 它用 send_msg 回应
      ▼
  send_msg(done, @测试) 完成报告：✓ 已完成… ▤ 产物… @测试 请测试   状态 → ✓ 完成；产物登记到公告；测试收到任务
      │
      ├─ send_msg(blocked)：「! 卡住：… @你」                    状态 → ! 卡住；主 Bot 跟进
      └─ 流程最后一个 Bot：send_msg(done, @总管) → 主 Bot 汇总产物，群进入 ◎ 待验收，在私聊里提醒你
                                        → 你 [确认完成] → 群完成，主 Bot 发总结
                                        → 你 [提修改意见] → 主 Bot 派给对应 Bot，回到上面的流程
```

**Bot 在 send_msg 里 @ 谁，谁就行动**
- @ 下一个流程的 Bot：它收到新任务，状态变为 ⟳ 工作中，这就是交接（例如产品 @编码、编码 @测试）。
- 全部完成时 @主 Bot：主 Bot 被唤醒，汇总产物，把群改为 ◎ 待验收，并在私聊里提醒你。
- 可以同时 @ 多个 Bot（并行分派）；卡住或需要决策时 @你，会推送到手机。

**⑥ 插话（Bot 运行中也可以 @ 它指导和修改）**
- 被 @ 的 Bot 正在这个群里干活时：
  1. 消息进入它的 durable 流程，在**下一步**生效（当前这次模型调用或工具调用结束后），不会额外调用模型立即回复。
  2. 你的气泡下面显示「已送达 · 等下一步」→「编码 已读取 ✓」；工作详情的轨迹里出现一条「✎ 插话」。
  3. 它读到后通常会用 `send_msg` 回应，例如「收到，改为只做邮箱登录」；决定性的内容由服务端记入项目记忆，并出现在公告的项目要点里。
- 它正挂起等你决策时，你的回复会直接唤醒它继续。
- 说「@编码 停一下」或在工作详情里点 [停止]，会中止当前任务，状态变为 ○ 待命。
- 被 @ 的 Bot 正在**别的群**里干活不受影响：每个群是独立的会话，可以并行。

**⑦ 交接、私信、防循环**
- 完成报告里的 @ 就是交接：下一个 Bot 收到任务，同时拿到上一个 Bot 的产物清单和说明。
- Bot 之间的私信不在群里刷屏，以「✉ A 私信了 B」卡片的形式出现。
- 同一条用户消息引发的 Bot 间往返超过 8 次，出现横幅「⏸ 已暂停」，并提供 [再允许 8 次] [结束这一轮]。

**⑨ 生命周期**

| 状态 | 怎么进入 | 侧栏 | 发生什么 |
|------|---------|------|---------|
| 进行中 | 创建 | 「群」列表 | 按流程协作 |
| ◎ 待验收 | 流程里最后一个 Bot 完成，主 Bot 汇总产物 | 「群」列表，带 ◎ | 主 Bot 在私聊里发待验收卡片，同时推送；工作台顶部显示「等你验收」 |

### 4.6 工作详情与运行轨迹 ★

工作详情有两种形态：**右侧面板**（简版，适合边聊边看）和**全屏轨迹**（完整版）。两种都支持**实时流式**（进行中的任务）和**回放**（已结束的任务）。打开时先用 `trace.history` 拉最近的记录，再带上最后的游标 `trace.subscribe`，服务端补齐中间的空档后实时推送（PROTOCOL 7.1）；关闭时退订。


**只有你点开某个 Bot 的时候才会看到它的 durable 详细记录**：点任务卡片上的「详情」、状态条里的某个成员，或者工作台里的「详情」。任务正在执行时流式推送，结束后可以回放；没有人看的时候，服务端只记录、不推送。


- 「任务指令」：原始指令，以及之后所有插话，按时间排列。

- 「项目」维度里还有两类特殊来源：「私聊」（不属于任何群的对话和转交的小事）和「定时任务」。

**④ 明细表**：按当前维度列出输入、输出、缓存读、请求数、费用和迷你趋势图。点某一行就下钻，例如 Bot → 这个 Bot 在各项目里的消耗，以及按阶段（私聊对话 / 干活 / 子代理 / 协调 / 记忆整理 / 压缩）的拆分。

**⑤ 其他**：顶部可以选时间范围（今天 / 7 天 / 30 天 / 90 天 / 自定义）和 Host；可以导出 CSV。没有配置单价的模型只显示 token，不显示费用。

### 4.10 技能

所有 Bot 共用一套技能，遵循 Agent Skills 规范（与 pi、Claude Code 兼容）：每个技能是一个目录，包含 `SKILL.md`（开头有 name 和 description），还可以附带脚本、参考资料和模板。

```text
┌────────────────────────────┬────────────────────────────────────────────────────────────┐
│ 技能                ＋ 新建│ web-auth-patterns                              [● 启用]    │
│ ⌕ 搜索技能                 │ 所有 Bot 可用 · 最近 7 天被调用 14 次（编码 12、测试 2）   │
│ [全部] 内置  我的  导入    │ 路径 ~/MacBot/skills/web-auth-patterns/                    │
│ ────────────────────────── │ ────────────────────────────────────────────────────────── │
│ ● agent-browser       内置 │ SKILL.md                                     [编辑] [预览] │
│   浏览器操作的完整说明     │ ---                                                        │
│ ● web-auth-patterns   我的 │ name: web-auth-patterns                                    │
│   登录/注册的实现规范      │ description: 实现登录、注册、找回密码时使用。包含密码规则、│
│ ● weekly-report       我的 │   会话管理、邮件验证流程和测试清单。                       │
│   周报格式与数据来源       │ ---                                                        │
│ ○ pdf-tools           导入 │ # 登录实现规范                                             │
│   已停用                   │ 1. 密码用 bcrypt，cost 12 …                                │
│                            │ ────────────────────────────────────────────────────────── │

│                            │ 对个别 Bot 停用   [ 无 ⌄ ]                                 │
└────────────────────────────┴────────────────────────────────────────────────────────────┘
```

- **来源**：内置（例如 agent-browser 自带的浏览器操作说明）、我的（新建的或者让 Bot 生成的）、导入（从文件夹、Git 地址或 zip 导入）。
- **启用/停用**：默认对所有 Bot 生效；可以对个别 Bot 停用。
- **Bot 怎么用**：
  - Bot 的上下文里只放技能的名字和描述；需要时 Bot 自己调用 `skill` 工具加载全文。
  - 你也可以在输入框里用 `/技能名` 强制它使用。
  - 子代理也能用技能。
- **新建**：手写，或者在对话里说「把刚才的做法整理成技能」，Bot 会生成一份草稿（列表里标为「草稿」），你在技能页点「发布」后才生效。
- 显示每个技能最近被哪些 Bot 调用过、调用了多少次。

### 4.11 Agent Computer（实时画面与接管）

### 4.12 记忆

## 8. 服务端组件与界面的对应关系

| 组件 | 职责 | 驱动哪些界面 |
|------|------|-------------|
| Gateway | 一个端口、密码鉴权；主连接 `/ws`（请求、事件、心跳、补发、运行轨迹）；画面连接 `/ws/screen`（按需）；`/api/v1` HTTP（文件、上传、导出）；`/admin` | 所有客户端 |
| **Orchestrator** ★ | 主 Bot 建群、转交小事、提醒验收；群消息路由（@、回复、没 @ 时交给主 Bot）；任务的创建、流转、交接；插话投递；防循环 | 群、状态条、任务卡片、完成报告、待验收卡片 |
| **Bot Runtime** ★ | **durable 执行**（落盘、可恢复、插话、挂起等待）；**`send_msg` 是群消息的唯一来源**；私聊对话；**子代理**；审批；停止 | 收到回复、工作详情、审批卡片 |
| **Tools / Skills** ★ | 工具注册表（文件、bash、agent-browser、子代理、网页、send_msg、记忆）；输出截断；技能扫描、加载和管理 | 工作详情的步骤、技能页、Bot 设置里的工具开关 |
| **Scheduler** ★ | 并发调度：全局上限、每个 Bot 的上限、同一个群内同一个 Bot 串行；排队；定时任务 | 工作台、排队原因 |
| Projects | 群（= 项目）、Home 目录、产物登记、公告生成、生命周期 | 公告、产物卡片、侧栏 |
| Memory | 三种记忆、自动分段和压缩、检索、后台整理（**只在服务端**） | 公告的项目要点 |
| **Usage** ★ | 每次模型调用都记账：Bot、群、任务、阶段（含子代理）、模型、token、费用；按小时和按天汇总 | 仪表盘、任务卡片上的 token 数 |
| Providers | 服务商和模型目录、流式输出、单价 | 模型设置 |
| Browser | **每个 Bot 一个** agent-browser 会话，并行任务按标签页隔离；画面流代理 | Agent Computer |
| Store | JSON 文件（JSONL 追加日志 + JSON 快照，没有数据库） | 搜索、断线补发、运行轨迹回放 |

客户端订阅的事件、调用的方法，以及它们的字段，以 [PROTOCOL.md](PROTOCOL.md) 第 5、6 章为准。

## 附录 A：Grok Bot 界面要点（参考来源）

- 三栏布局：侧栏 / 会话 / 右侧上下文面板。侧栏有分组、置顶头像磁贴、「Hidden Bots N」。
- 用户消息是黑色气泡，Bot 消息是浅灰气泡；提问卡片用 A/B/C 选项；任务卡片带「Running」状态和操作按钮。
- 右侧面板默认显示「X's screen」和 Routines；⚙ 进入 Settings；定时任务页有 Active 开关、Delete、Test run、Instruction、When to run、Run history。
- 电脑视图覆盖整个窗口，右上角是「Teach a task」和收起按钮。
- 群聊：2–6 个 Bot；不 @ 时由 Bot 自己决定谁回应；用回复形成线程；审批、密码请求和草稿不在群里出现；群有 Group name 和 Description。
- 审批：Allow once / Always allow / Deny。

Mac Bot 在 Grok 的基础上新增了：**主 Bot 当负责人（只协调不干活，做完提醒验收）**、**群消息只来自 `send_msg`，干活过程按需查看**、**子代理**、**系统维护的公告和产物清单**、**按群并行**、**工作台**和**仪表盘**。

# 08 · 交互细则：焦点顺序、键盘、无障碍、细节规则

> 第 4 节的细节规则参考了 Grok Bot、nightly-labs/openbot 和 Telegram 的通行做法（产品参考，不复用代码），文中逐条注明来源。

## 1. 焦点顺序（Tab 顺序）

原则：**先「我现在要处理的事」，再「我在哪里」，最后「其他」**。打开一个会话时，焦点默认落在**输入框**（聊天应用的习惯，打开就能打字）；关闭弹层后，焦点回到打开它的那个控件。

### 1.1 macOS 主窗口

| 顺序 | 区域 | 说明 |
|------|------|------|
| 0（默认焦点） | 输入框 | 打开或切换会话后，焦点自动放在这里 |
| 1 | 输入框里的按钮：＋ → @ → 发送 | |
| 2 | 消息流 | 整个消息流算一个焦点，用 ↑↓ 在消息之间移动（不是每条消息一个 Tab 位）；在某条消息上按 ↵ 进入它的卡片，在卡片里用 Tab 遍历按钮；Esc 退回消息流 |
| 3 | 会话头部：状态条（←→ 在成员之间移动）→ 搜索 → 面板开关；公告只在群信息中 | |
| 4 | 右面板：页头（‹ 返回 → ⚙ → 收起）→ 内容，按从上到下的分区，每个分区算一个 Tab 位，区内用 ↑↓ | 「等你处理」分区排在最前 |
| 5 | 侧栏：Host 切换 → 新建 → 搜索 → 会话列表（一个 Tab 位，↑↓ 移动，↵ 打开，⌘↵ 在右面板打开）→ 底部导航 | |

- **F6 / ⇧F6**：在四个大区之间循环（输入框 → 消息流 → 右面板 → 侧栏），不经过每个控件。
- **需要你处理的卡片优先**：会话里有待处理的审批、提问或验收时，按 **⌘J** 直接把焦点放到最近一张待处理卡片的主按钮上。
- 对话框和弹层：打开时焦点放在第一个输入框（没有输入框时放在主按钮上）；Tab 只在弹层内部循环；Esc 关闭。危险操作（删除、拒绝）**永远不是**默认焦点。

### 1.2 手机（TalkBack / VoiceOver 顺序）

读屏顺序按视觉从上到下，但做以下分组：
1. 顶栏：返回 → 标题（群名 + 状态读成一句「登录功能，进行中，4 位成员」）→ 右侧按钮。
2. 「等你处理」条（如果有）：读作一个按钮「等你处理 1 项：登录功能验收」。
3. 消息：每条消息读成一句「编码，10 点 32 分：收到，正在调整」；带卡片的消息，卡片作为子元素，按钮单独可聚焦。
4. 输入栏：＋ → 输入框 → @ / 发送。
5. 底部导航。

## 2. 键盘快捷键（macOS）

在 DESIGN.md 4.15 的基础上补充：

| 快捷键 | 动作 |
|--------|------|
| ⌘J | 跳到最近一张待处理卡片（审批 / 提问 / 验收） |
| ⌘↵ | 在待处理卡片上执行主按钮（允许一次 / 确认完成）；在输入框里是「发送」的另一种写法 |
| ⌘E | 在群里打开「编辑公告」 |
| ⌘I | 打开或关闭右面板 |
| ⌘⇧T | 打开当前任务的全屏轨迹 |
| ⌥↑ / ⌥↓ | 切换到上一个 / 下一个会话 |
| ⌥⇧↓ | 跳到下一个有待处理事项的会话 |
| ↑（输入框为空时） | 编辑上一条自己发的消息 |
| R（焦点在消息上） | 回复（引用） |
| R / Q（焦点在消息上） | 回复 / 引用这条消息 |
| 1 … 9（焦点在提问卡片上） | 选择第 N 个选项 |
| F6 / ⇧F6 | 在大区之间切换焦点 |

## 3. 无障碍

| 项 | 规则 |
|----|------|
| 对比度 | 正文和按钮文字 ≥ 4.5:1（实测见 01 §3.2）；`text.tertiary`（2.5:1）只用于时间、占位这类次要信息，**不能单独承载信息**（例如「已过期」同时把选项变灰） |
| 状态不只靠颜色 | 所有状态都同时有**图形**（⟳ ✓ ⚠ ! ◎ …）和**文字**，色盲用户也能分辨 |
| 字号缩放 | macOS 设置里有「消息字号：小 / 标准 / 大」（13 / 14 / 16）；手机跟随系统字号（Dynamic Type / 字体缩放），消息区最大放大到 200%，顶栏和底栏最大 130%。放大后气泡最大宽度不变，换行增多 |
| 触控目标 | 手机 ≥ 48dp（Android）/ 44pt（iOS）；桌面可点击区域 ≥ 24×24 |
| 读屏标签 | 图标按钮都有标签（例如「打开右面板」「添加附件」）；头像读作「编码，工作中」；转圈读作「工作中」；任务卡片读作「任务：实现登录，工作中，已 25 分钟，详情按钮」 |
| 动效 | 系统开启「减弱动态效果」时：转圈改成静态图标，位移动画改成 120ms 淡入淡出，扫光进度条改成静态 30% |
| 透明度 | 系统开启「降低透明度」时，自动退回不透明模式 |
| 实时更新 | 状态变化通过读屏的「礼貌」通知播报（不打断）；审批和接管请求用「立即」通知 |

## 4. 细节规则

| 规则 | 做法 | 参考 |
|------|------|------|
| **头像** | 默认是豆豆（10 色之一）；也可以换成 **emoji**（emoji 居中显示在原来的底色上，字号 = 头像直径 × 0.55，不画眼睛）或**图片**（裁成圆形，不画眼睛）。主 Bot 无论用哪种，都在右下角加一个 40% 大小的眼镜徽章，保证一眼认出 | Grok Bot：Bot 可以自选头像和颜色 |
| **头像颜色分配** | 新建 Bot 时，取 `avatar.0…9` 里**当前使用次数最少**的颜色；次数相同时取序号最小的。主 Bot 固定 `avatar.0`。用户可以改 | Telegram：按 id 给头像分色，保证相邻的人颜色不同 |
| **群头像** | 1–3 个成员侧向错位堆叠，主 Bot 在左侧最前层，其余按加入顺序；超过 3 个保留 2×2 网格，主 Bot 固定左上。超过 4 个时，第 4 格显示「+N」（`bg.active` 底，11px 600 `text.secondary`）。成员计数包含主 Bot，不因头像布局隐藏成员 | 用户确认的少成员堆叠与现有多成员网格 |
| **名字截断** | 会话列表、成员行：单行，末尾省略号；群名最长 32 字，Bot 名最长 16 字（新建时校验）；气泡里的名字不截断；工具栏标题在中间截断（保留开头和结尾） | Telegram |
| **时间格式** | 时间不在气泡里，显示位置见 06 §2.1。今天：`HH:mm`；昨天：「昨天」；7 天内：「周一」；更早：`MM/DD`；跨年：`YYYY/MM/DD`。悬停（手机长按）显示完整时间 | Telegram |
| **未读与注意力** | 会话行右侧只显示一个标记，优先级：⚠ 审批 > ◎ 待验收 > ! 卡住 > ⟳ 工作中 > 未读数 > 无；静音的会话未读数为灰色 | openbot：按注意力排序；Zeron：按需要处理的程度排序会话 |
| **会话排序** | 主 Bot 固定第一；其余群按「有待处理事项」优先，再按最后活动时间；置顶的群排在主 Bot 之后 | 同上 |
| **长消息** | 超过 30 行的 Bot 消息折叠，显示「展开全文」；代码块超过 20 行折叠 | Grok Bot |
| **图标（Android）** | 三端统一用 **Lucide**（线宽 1.5），Android 不换成 Material Symbols，保证 Android 和 iOS 外观一致；只有系统通知的小图标按 Android 要求用单色剪影 | 本项目约定（AGENTS：三端 token 名一致） |
| **审批卡片过期** | 任务结束或被停止时，未处理的审批变为 `expired`，卡片变灰；通知同步撤回 | openbot：fail closed |
| **防循环** | 同一条用户消息引发的 Bot 间往返达到上限（默认 8 次）时暂停，在群里显示 `loop_paused` | openbot：每个根请求最多 8 次自动委派 |
| **公告长度** | 正文最长 8,000 字；超过 2,000 字时，右面板的公告卡片默认折叠到 12 行，显示「展开」 | — |
| **空状态** | 每个列表都有空状态：一句说明 + 一个能直接做的动作（例如「还没有定时任务。对任意 Bot 说『每天 9 点…』，或点 ＋ 新建」） | Grok Bot |

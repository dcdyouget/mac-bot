# v1.1 §3 Android audit — approvals

- Existing: approval decisions already support allow once, always allow when the operation permits it, and deny. The settings screen had no approval mode or rule editor.
- Corrected: added the two protocol modes (`always_allow` default and `require`), custom ask-first/auto-allow rules scoped to all Bots or one Bot, and deletion for user rules. Built-in rules remain visible and read-only; settings writes preserve the server-supplied built-ins.
- Safety: settings are not editable until loaded; writes lock the controls, recheck Host identity after acquiring the mutex, serialize from the latest settings snapshot, and target the initiating Host. Dialog, saving, and error state resets on Host switch. Unknown bot scopes display the stored id; custom rules show “你添加的”, and failures use a localized message.
- Constraints: protocol represents rules as text matching the tool name, generated summary, or argument literal; the editor exposes that text directly. Built-in rules are protected server-side.

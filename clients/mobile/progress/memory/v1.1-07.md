# v1.1 §7 Android slash-skill audit

- Existing behavior: `/` opens a picker above the composer, selecting a skill stores it as a chip, and sent-message “loaded” labels derive only from persisted `loaded_skills`; historical disabled/deleted skills remain identifiable when the service reports them as loaded.
- Fixed: the picker now shows a Recent section and all-skill section when the query is empty. Recent ordering uses only `last_invoked_at`, filters to successful calls from the previous seven days, excludes disabled skills, and caps at three.
- Added a deterministic unit test covering stale calls, edit timestamps without calls, recency order and disabled skills.
- Follow-up fix: no-match state now offers a localized create action. It routes to the skills page with the typed query prefilled in the new-skill editor, avoiding the previous dead end.
